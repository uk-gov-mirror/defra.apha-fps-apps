# Job State "Initiated" Implementation Analysis

## Current Implementation Overview

### Architecture Pattern
```
API → EventBridge → ECS Task → Worker → PostgreSQL
```

**Key Point**: Currently, the worker is **NOT** pulling jobs from a queue. Each job is started as an independent ECS task via EventBridge.

- **No Redis/Cache involved** in current job queuing
- **No polling mechanism** - ECS tasks are event-driven
- **Distributed lock** in PostgreSQL (`fps.job_lock`) prevents concurrent execution
- `jobExecutionId` generated by API, passed through EventBridge → ECS environment variables → Worker

### Current State Flow
```
1. API generates jobExecutionId (GUID)
2. API publishes event to EventBridge
3. EventBridge routes to ECS task (async)
4. Worker starts → JobOrchestrator.RunAsync()
   - Acquires distributed lock in PostgreSQL
   - Creates TblJobQueue record with Status=RUNNING
   - Executes job logic
   - Updates status to COMPLETED/FAILED/etc
   - Releases lock
```

### 3. **API Layer: Trigger Endpoint**

**Responsibilities**:
1. Validate the trigger request

**Controller Action**:
```csharp
[HttpPost("{jobName}")]
public async Task<IActionResult> TriggerJob(
    string jobName,
    [FromBody] TriggerJobRequest request,
    CancellationToken cancellationToken)
{
    // 1. Validate request
    if (string.IsNullOrWhiteSpace(jobName))
        return BadRequest("jobName required");
    
    var validationResult = await _jobValidationService.ValidateJobAsync(
        jobName, 
        request.Parameters, 
        cancellationToken
    );
    if (!validationResult.IsValid)
        return BadRequest(validationResult.Errors);
    
    // 2. Generate ID and timestamp
    var jobExecutionId = Guid.NewGuid().ToString("N");
    var acceptedAtUtc = DateTime.UtcNow;
    var requestedBy = User.Identity?.Name ?? "system";
    
    // 3. Create Initiated job record
    var jobQueueId = await _jobExecutionRepository.CreateInitiatedJobAsync(
        jobName: jobName,
        jobExecutionId: jobExecutionId,
        requestedBy: requestedBy,
        requestedAtUtc: acceptedAtUtc,
        runMode: RunMode.Manual,  // or from request
        cancellationToken: cancellationToken
    );
    
    // 4. Publish event to EventBridge
    await _eventBridgePublisher.PublishAsync(
        jobName: jobName,
        jobExecutionId: jobExecutionId,
        requestedBy: requestedBy,
        requestedAtUtc: acceptedAtUtc,
        cancellationToken: cancellationToken
    );
    
    // 5. Return 202 Accepted with tracking info
    return Accepted(new
    {
        jobExecutionId = jobExecutionId,
        jobName = jobName,
        status = "Initiated",
        requestedBy = requestedBy,
        requestedAtUtc = acceptedAtUtc,
        trackingUrl = $"/api/jobs/{jobExecutionId}/status"
    });
}
```

```csharp
// JobExecutionRepository.cs
public async Task<Guid> CreateInitiatedJobAsync(
    string jobName,
    string jobExecutionId,
    string requestedBy,
    DateTime requestedAtUtc,
    RunMode runMode,
    CancellationToken cancellationToken = default)
{
    // Get job definition
    var job = await _dbContext.TblJobMasters
        .FirstOrDefaultAsync(j => j.JobName == jobName, cancellationToken)
        ?? throw new InvalidOperationException($"Job '{jobName}' not found");
    
    // Get Initiated status ID from fps.job_status
    var initiatedStatus = await _dbContext.TblJobStatus
        .FirstOrDefaultAsync(s => s.Status == "Initiated", cancellationToken)
        ?? throw new InvalidOperationException("Initiated status not configured");
    
    // Create new job_queue record
    var jobQueueId = Guid.NewGuid();
    var jobQueueRecord = new TblJobQueue
    {
        JobQueueId = jobQueueId,
        JobExecutionId = Guid.Parse(jobExecutionId),
        JobId = job.JobId,
        StatusId = initiatedStatus.StatusId,
        RequestedBy = requestedBy,
        RequestedAtUtc = requestedAtUtc,
        StartDateTime = null,  // Not started yet
        EndDateTime = null,
        ErrorMessage = null,
        CreatedAt = DateTime.UtcNow,
        UpdatedAt = DateTime.UtcNow
    };
    
    await _dbContext.TblJobQueues.AddAsync(jobQueueRecord, cancellationToken);
    
    // Log state change
    await _jobQueueLogRepository.LogStateChangeAsync(
        jobQueueId: jobQueueId,
        statusId: initiatedStatus.StatusId,
        performedBy: requestedBy,
        note: "Job triggered via API - Initial state",
        logTime: DateTime.UtcNow,
        cancellationToken: cancellationToken
    );
    
    await _dbContext.SaveChangesAsync(cancellationToken);
    
    return jobQueueId;
}
```

### 4. **Worker Layer: Find and Transition Record**

**File**: `src/Apha.BatchJobs/Apha.BatchJobs.Worker/Program.cs`

**Responsibilities**:
1. Read `BATCH_JOB_EXECUTION_ID` from environment
2. Find existing `fps.job_queue` row by jobExecutionId
3. Validate it is in `Initiated` state
4. Acquire distributed lock
5. Transition from `Initiated` to `Running`
6. Continue with job execution logic
7. Update to terminal state on completion
8. Release lock

**Worker Startup Flow**:
```csharp
// src/Apha.BatchJobs/Apha.BatchJobs.Worker/Program.cs

// ... existing setup code ...

var jobExecutionIdEnv = Environment.GetEnvironmentVariable("BATCH_JOB_EXECUTION_ID")
    ?? throw new InvalidOperationException("BATCH_JOB_EXECUTION_ID not set");

var jobExecutionId = Guid.Parse(jobExecutionIdEnv);

// Find the existing Initiated record
var jobQueueRecord = await _jobExecutionRepository.GetJobQueueByExecutionIdAsync(
    jobExecutionId,
    cancellationToken
);

if (jobQueueRecord == null)
{
    _logger.LogError($"Job record not found for execution ID {jobExecutionId}");
    throw new InvalidOperationException(
        $"Job execution record not found. JobExecutionId: {jobExecutionId}"
    );
}

// Validate it's in Initiated state
if (jobQueueRecord.StatusId != (int)JobStatus.Initiated)
{
    _logger.LogError(
        $"Job {jobExecutionId} is not in Initiated state. " +
        $"Current status: {(JobStatus)jobQueueRecord.StatusId}"
    );
    throw new InvalidOperationException(
        $"Job must be in Initiated state to start. " +
        $"Current state: {(JobStatus)jobQueueRecord.StatusId}"
    );
}

var jobQueueId = jobQueueRecord.JobQueueId;
var jobId = jobQueueRecord.JobId;

// Acquire distributed lock BEFORE changing state
var lockAcquired = await _batchLockRepository.AcquireLockAsync(
    jobQueueId: jobQueueId,
    acquiredBy: Environment.UserName,
    timeoutSeconds: 3600,
    cancellationToken: cancellationToken
);

if (!lockAcquired)
{
    _logger.LogError($"Failed to acquire lock for job {jobExecutionId}");
    throw new InvalidOperationException(
        $"Could not acquire execution lock. Job may already be running."
    );
}

try
{
    // Transition from Initiated to Running
    await _jobExecutionRepository.TransitionJobStatusAsync(
        jobQueueId: jobQueueId,
        fromStatus: JobStatus.Initiated,
        toStatus: JobStatus.Running,
        transitionTime: DateTime.UtcNow,
        cancellationToken: cancellationToken
    );
    
    // Continue with orchestrator (uses same jobQueueId)
    var result = await orchestrator.RunAsync(
        jobQueueId: jobQueueId,
        cancellationToken: linkedCts.Token
    );
    
    // Orchestrator handles transition to Running, then to terminal state
}
finally
{
    // Release lock
    await _batchLockRepository.ReleaseLockAsync(
        jobQueueId: jobQueueId,
        cancellationToken: cancellationToken
    );
}
```

**New Repository Method - Transition State**:
```csharp
// JobExecutionRepository.cs
public async Task TransitionJobStatusAsync(
    Guid jobQueueId,
    JobStatus fromStatus,
    JobStatus toStatus,
    DateTime transitionTime,
    string changedBy = "system",
    CancellationToken cancellationToken = default)
{
    var record = await _dbContext.TblJobQueues
        .FirstOrDefaultAsync(x => x.JobQueueId == jobQueueId, cancellationToken)
        ?? throw new InvalidOperationException(
            $"Job queue record not found. JobQueueId: {jobQueueId}"
        );
    
    var currentStatus = (JobStatus)record.StatusId;
    
    // Validate state transition is allowed
    if (currentStatus != fromStatus)
    {
        throw new InvalidOperationException(
            $"Invalid state transition. " +
            $"Expected: {fromStatus}, Actual: {currentStatus}"
        );
    }
    
    // Get target status ID from fps.job_status
    var targetStatusRecord = await _dbContext.TblJobStatus
        .FirstOrDefaultAsync(s => (JobStatus)s.StatusId == toStatus, cancellationToken)
        ?? throw new InvalidOperationException(
            $"Status '{toStatus}' not found in job_status lookup"
        );
    
    // Update the record
    record.StatusId = targetStatusRecord.StatusId;
    record.UpdatedAt = DateTime.UtcNow;
    
    // Set StartDateTime when transitioning to Running
    if (toStatus == JobStatus.Running)
    {
        if (record.StartDateTime == null)
        {
            record.StartDateTime = transitionTime;
        }
    }
    
    // Set EndDateTime when transitioning to terminal state
    if (IsTerminalState(toStatus))
    {
        record.EndDateTime = transitionTime;
    }
    
    _dbContext.TblJobQueues.Update(record);
    
    // Log state change in audit table
    await _jobQueueLogRepository.LogStateChangeAsync(
        jobQueueId: jobQueueId,
        statusId: targetStatusRecord.StatusId,
        performedBy: changedBy,
        note: $"Status transitioned from {fromStatus} to {toStatus}",
        logTime: DateTime.UtcNow,
        cancellationToken: cancellationToken
    );
    
    await _dbContext.SaveChangesAsync(cancellationToken);
    
    _logger.LogInformation(
        "Job state transitioned. JobQueueId: {JobQueueId}, " +
        "From: {FromStatus}, To: {ToStatus}, Timestamp: {Timestamp}",
        jobQueueId, fromStatus, toStatus, transitionTime
    );
}

private static bool IsTerminalState(JobStatus status)
{
    return status switch
    {
        JobStatus.Completed => true,
        JobStatus.Failed => true,
        JobStatus.Cancelled => true,
        JobStatus.Skipped => true,
        _ => false
    };
}
```

## Analysis: Cache/Redis Impact

### Current System Does NOT Use Redis for Job Queuing

Your codebase uses:
1. **EventBridge** for event distribution (AWS service, pub/sub)
2. **ECS** for task orchestration (AWS service, managed tasks)
3. **PostgreSQL** for persistent storage and distributed locks
4. **No Redis** for job queue management
5. **No polling mechanism** - Tasks launched directly by EventBridge

**Why no Redis?** 
- Each job is a separate, independent ECS task
- EventBridge routes events directly to ECS
- No need for in-memory queue; PostgreSQL serves as audit trail

### Adding "Initiated" State Does NOT Change This Architecture

The new state management:
- ✅ Still uses PostgreSQL for all persistence
- ✅ Still uses EventBridge for event routing
- ✅ No Redis involvement needed
- ✅ No polling queues
- ✅ Just adds state transition tracking

**Key insight**: This is purely adding **state tracking** to an already event-driven architecture. Not converting to queue-based architecture.

### If You Later Decide on Queue-Based Architecture (Optional Future Work)

Only if you need **job queuing** (multiple workers polling jobs), would you consider:

```
API → PostgreSQL Queue Table → Worker Polls (no Redis needed)
      or
API → Redis Queue → Worker Polls (in-memory, less durable)
```

But this is **NOT required** for the current proposal. Stick with EventBridge.

## Handling Scheduled Jobs vs Manual Trigger

### Scheduled Jobs (EventBridge)

**Flow**:
1. EventBridge event triggers automatically
2. ECS task starts with environment variables
3. Worker reads `BATCH_JOB_EXECUTION_ID`
4. Finds existing `Initiated` record created by... **wait, who creates it?**

**Problem**: EventBridge events are automatic. No API to create the record first.

**Solution Options**:

**Option A: EventBridge Event → Lambda Function (Recommended)**
```
EventBridge Rule
    ↓
Lambda Function (new)
    ├─ Extract job details from event
    ├─ Generate jobExecutionId
    ├─ Create Initiated record in DB
    └─ Publish to SQS/ECS
        ↓
ECS Worker picks up with jobExecutionId
```

**Option B: Worker Creates for Scheduled (Fallback)**
```
EventBridge Rule → ECS Worker
    ↓
Worker reads BATCH_JOB_NAME (no BATCH_JOB_EXECUTION_ID)
    ├─ Generate jobExecutionId
    ├─ Create Initiated record
    └─ Transition to Running
        ↓
Continue execution
```

**Option C: Pre-populate Schedule (Complex)**
```
Scheduled Task (15 min before)
    ├─ Read scheduled jobs
    ├─ Create Initiated records for each
    └─ Wait for EventBridge to trigger
        ↓
Worker finds existing Initiated record
```

**Recommendation**: **Option B (Worker Creates for Scheduled)** is simplest:
- Scheduled jobs behave as they do now (EventBridge doesn't need to know about records)
- Manual triggers ALWAYS create records via API first
- Different code paths, but minimal changes

```csharp
// Worker startup
if (Environment.GetEnvironmentVariable("BATCH_RUN_MODE") == "Scheduled")
{
    // Scheduled: Create record if doesn't exist
    var jobQueueId = await GetOrCreateScheduledJobRecordAsync(...);
}
else
{
    // Manual: Record must already exist from API
    var jobQueueId = await GetManualJobRecordAsync(...);
}
```

## Concerns & Mitigations

| Concern | Mitigation |
|---------|-----------|
| Worker crashes before seeing record | Watchdog monitors stuck Initiated jobs (>30 min), alert ops |
| Duplicate submissions via API | UNIQUE constraint on `jobexecutionid` ensures one record per execution |

## Summary: Revised Data Flow

```
┌─────────────────────────────────────────────────────────────────┐
│ MANUAL TRIGGER (UI/API)                                         │
├─────────────────────────────────────────────────────────────────┤
│ 1. API.TriggerJob()                                              │
│    ├─ Validate request                                          │
│    ├─ Generate jobExecutionId                                   │
│    ├─ Create job_queue record (Initiated)                       │
│    ├─ Log to job_queue_log                                      │
│    └─ Return 202 Accepted                                       │
│                                                                   │
│ 2. Publish EventBridge event (async)                            │
│    └─ jobexecutionid in event payload                           │
│                                                                   │
│ 3. EventBridge routes to ECS task                               │
│    └─ Pass BATCH_JOB_EXECUTION_ID env var                       │
│                                                                   │
│ 4. Worker.Main()                                                │
│    ├─ Read BATCH_JOB_EXECUTION_ID                               │
│    ├─ Find job_queue record (Initiated)                         │
│    ├─ Validate status is Initiated                              │
│    ├─ Acquire lock                                              │
│    ├─ Transition Initiated → Running                            │
│    ├─ Run orchestrator                                          │
│    │   ├─ Execute job logic                                     │
│    │   └─ Transition → Terminal                                 │
│    └─ Release lock                                              │
│                                                                   │
│ 5. Job_queue_log audit trail created for all transitions        │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ SCHEDULED JOB (EventBridge automatic)                           │
├─────────────────────────────────────────────────────────────────┤
│ 1. EventBridge fires on schedule                                │
│    └─ Route to ECS task                                         │
│                                                                   │
│ 2. Worker.Main()                                                │
│    ├─ Read BATCH_JOB_NAME (no jobexecutionid in env)            │
│    ├─ Generate jobexecutionid                                   │
│    ├─ Create job_queue record (Initiated) ← DIFFERS             │
│    ├─ Acquire lock                                              │
│    ├─ Transition Initiated → Running                            │
│    ├─ Run orchestrator                                          │
│    │   └─ ... same as manual ...                                │
│    └─ Release lock                                              │
│                                                                   │
│ (Backward compatible with current scheduled flow)               │
└─────────────────────────────────────────────────────────────────┘

DB State Progression:
  Initiated (API/Worker Created)
        ↓
  Running (Job Logic Active)
        ↓
  Completed / Failed / Cancelled / Skipped (Terminal State)
```
